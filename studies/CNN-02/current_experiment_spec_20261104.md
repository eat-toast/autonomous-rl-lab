## 1. 실험에서 풀고 있는 문제

10×10 장애물 지도에서 왼쪽 위 (0,0)에서 오른쪽 아래 (9,9)까지 이동한다.
코인은 없다. 지도는 에피소드 동안 고정되고 에이전트 위치만 바뀐다.
상하좌우 4행동이며 대각선은 없다. 벽/경계 충돌은 제자리이며 1행동을 소비한다.

일반 이동 -0.01, 충돌 -0.05, 도착 +1 중 하나의 보상만 적용한다.
도착하면 즉시 성공 종료한다. 100행동까지 도착하지 못하면 시간 제한 실패다.
100번째 행동에 도착하면 성공이다.

각 칸을 벽일 확률 0.2로 무작위 생성하고 출발/목표를 비운다.
A*로 출발→목표 경로가 있는 지도만 수락한다. 목표 경로를 나중에 뚫는 생성 방식은 아니다.
실제 벽 비율은 지도마다 달라진다. 소개 이미지의 훈련 지도 0번은 벽 18개/18%, 최단 18행동이다.
훈련 16개 지도의 평균 벽 비율은 19.125%, 개발 검증 8개는 20.625%다.
A* 길이는 훈련 18~20행동, 개발 검증은 모두 18행동이다.
현재 생성기는 사람이 설계한 긴 복도형 미로가 아니라 무작위 장애물 격자 환경이다.

## 2. 지도 40개를 세 묶음으로 분리

| 묶음 | 지도 수 | 학습 중 역할 | 가중치 갱신에 사용 | 현재 평가 상태 |
|---|---:|---|---|---|
| 훈련 train | 16 | 매 새 에피소드에 하나를 무작위로 선택해 경험 수집 | 예 | 마지막 모델의 익숙한 지도 성능도 별도 평가 |
| 개발 검증 validation | 8 | 500 환경 스텝마다 성능 확인, 설정 선택 | 아니오 | 현재 공개한 비교 결과의 평가 세트 |
| 최종 테스트 test | 16 | 연구 선택이 끝난 뒤 최종 확인에 사용할 예약 세트 | 아니오 | 아직 평가하지 않음 |

지도 생성 규칙/크기/출발/목표/보상은 같지만 실제 벽 배치가 다르다.
생성 seed 구간과 격자 해시를 분리해 같은 지도가 두 묶음에 들어가지 않도록 했다.
각 알고리즘/조건/학습 seed는 같은 지도 묶음을 사용한다.
현재는 훈련 16개를 반복 선택하는 유한 pool이다. 매 에피소드마다 완전히 새 미로를 생성하지 않는다.
무작위 선택이므로 각 지도를 정확히 같은 횟수/스텝만큼 학습한다는 뜻은 아니다.

세 묶음을 나눈 목적은 질문을 구분하기 위해서다.

- 훈련 지도 평가: 이미 연습한 지도에서 길을 찾는가?
- 개발 검증 평가: 학습에 쓰지 않은 같은 크기의 지도에서도 길을 찾는가?
- 최종 테스트: 개발 과정에서 반복 확인하지 않은 세트에서도 성능이 유지되는가?

현재 0/8 또는 3/8 같은 숫자는 **개발 검증** 결과다. 최종 테스트 결과라고 부르면 안 된다.
개발 검증은 가중치 업데이트에 쓰이지 않지만 설정 선택에는 쓰이므로 완전히 손대지 않은
최종 시험지와는 다르다. 지도 그림이 달라지는 것은 의도한 분리이며 모델을 매번 새 지도에서
다시 학습시킨 뒤 평가하는 구조가 아니다.

## 3. 모델과 입력

매 행동 시 float32 `3×10×10` 텐서를 받는다.
채널 1은 벽, 채널 2는 현재 위치 한 칸, 채널 3은 목표 한 칸을 표시한다.
전체 지도를 보며 A* 경로·다음 정답 행동·방문 횟수는 입력하지 않는다.
출발점은 항상 고정되어 있지만 별도 출발점 채널은 없다.

네트워크:

```text
3×10×10
→ Conv(3→16, 3×3, padding 1) + ReLU
→ Conv(16→32, 3×3, padding 1) + ReLU
→ Flatten(3,200)
→ Linear(3,200→64) + ReLU
→ Linear(64→4)
```

출력은 상하좌우 행동별 Q값 4개이며 확률/softmax가 아니다.
기본 모델은 가중치와 bias를 합해 한 네트워크당 **210,212개** 파라미터다.
별도 target network도 같은 크기로 존재한다. 두 네트워크가 있다는 뜻이 Double DQN은 아니다.
FC만 128로 바꾼 변형은 **415,332개**이며 여전히 같은 DQN 알고리즘이다.

CNN은 지도를 처리하는 네트워크 형태, DQN은 그 Q값을 학습하는 알고리즘이다.
현재 구현은 DQN이며 Double/Dueling/Dueling Double/PER/Rainbow는 아직 구현하지 않은 계획이다.
다른 크기는 같은 입력 표현을 쓰되 크기별로 새 모델을 학습하는 계획이다.
현재 Flatten/Linear 크기 때문에 10×10 가중치를 그대로 20×20에 넣는 구조는 아니다.

## 4. 현재 B 학습 설정

| 설정 | 값 | 의미 |
|---|---|---|
| 학습 seed | 0, 1, 2 | 초기 가중치·탐색·경험 샘플링을 달리하는 독립 모델 3개 |
| 환경 스텝 | 각 20,000 | 모델 하나가 행동한 총 횟수. 20,000 에피소드가 아님 |
| 전체 상호작용 | 60,000 | 세 모델의 학습량 합계. 하나의 모델을 60,000스텝 학습한 것이 아님 |
| 탐색 | epsilon 1.0→0.1, 16,000스텝 선형 감소 | 처음에는 무작위 행동, 이후 Q값 활용 비중 증가 |
| Replay | 최근 2,000개 전이 | 상태·행동·보상·다음 상태·목표 종료 여부를 보관 |
| Replay 샘플링 | 균등 무작위, 배치 내 비복원 | 오래된 순서로 학습하는 FIFO 샘플링이 아님 |
| 배치 | 32 | 한 번 업데이트에서 꺼내는 경험 개수 |
| 학습 시작 | 64스텝 | 경험을 모은 뒤 업데이트 시작 |
| 학습 주기 | 환경 4스텝마다 | 20k 조건에서 optimizer 4,985회 |
| Optimizer/lr | Adam / 0.001 | 가중치 갱신 규칙과 크기 |
| Loss | Huber | 예측 Q값과 TD target 차이 |
| gamma | 0.99 | 미래 보상의 할인율 |
| Target | 환경 100스텝마다 hard copy | 목표 계산 네트워크 동기화 |
| gradient clipping | norm 10 | 과도한 갱신 제한 |
| 실행 | CPU 1 thread | 현 실험은 GPU 학습 아님 |
| 시간 제한 | seed별 soft180초/hard210초 | 완료 전 제한 도달은 성공 실행으로 취급하지 않음 |

Replay는 에피소드가 바뀌어도 유지되며, 다음 경험이 들어오면 가장 오래된 슬롯을 덮어쓴다.
첫 2,000스텝 경험은 4,000스텝이 끝나면 모두 교체된다.
20,000스텝에는 18,001~20,000번째 경험만 남는다. 버퍼를 비워도 가중치/타깃/Adam 상태가
자동으로 초기화되지는 않는다. Replay 내용은 현재 checkpoint에 저장하지 않아 그대로 이어가는
완전 resume는 지원하지 않는다.

## 5. 평가·그래프·선택

개발 검증은 epsilon=0, 즉 Q값이 가장 큰 행동만 고른다. 평가 중 가중치·Replay를 갱신하지 않는다.
학습 전 0스텝, 이후 500스텝 간격 및 마지막 20,000스텝에서 같은 8개를 평가한다.
마지막 모델에서 8개 지도×3개 학습 seed=24회 평가다. 서로 다른 지도 24개가 아니다.
같은 결정적 평가를 반복해서 독립 표본 수를 늘리지 않는다.

- 훈련 return: 탐색 행동이 포함된 각 에피소드의 보상 합.
- 보상 곡선: 원본과 최근 20개 에피소드 이동평균. 마지막 미완료 에피소드는 제외.
- 성공률: 목표 도착 비율. 훈련 미로 greedy/새 미로 greedy를 별도 계산.
- 경로 효율: 성공 에피소드에서만 A* 최단 길이/실제 행동 수.
- 편차: 학습 seed 3개의 평균과 표본 표준편차. 신뢰구간이 아님.

`best.pt`는 검증 성공률→성공 경로 효율 순의 중간 최고 모델이다.
최근 4단계 비교와 B 선택에는 `latest.pt`인 마지막 모델을 공통 기준으로 썼다.
그 선택은 평균 검증 성공률→낮은 seed 표준편차→성공 경로 효율이며 동률이면 이전 조건 유지다.

A*는 지도 도달 가능성 확인과 최단 기준을 계산하는 비교 도구다.
현재 DQN에게 A*의 정답 경로나 전문가 전이를 주지 않는다.
