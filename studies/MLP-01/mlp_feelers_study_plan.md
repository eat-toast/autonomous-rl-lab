# 더듬이 8개로 미로를 풀 수 있을까?

원본 묶음 ID는 `MLP-01`이다. MLP1은 **MLP-01-기본관측**(원본 조건 `MLP10`), MLP2는 **MLP-02-이웃방문**(원본 조건 `MLP14`)이다. 아래는 당시 실행 전 설계이며, 실행 결과는 [실험 목록](../../docs/experiment_index.md)에서 확인한다.

## 연구 질문과 조건

첫 질문은 주변 한 칸과 출구 방향만 보는 MLP가 미로를 얼마나 안정적으로 푸는가이다.
두 번째 질문은 두 칸 왕복이 반복될 때, 이웃 방문 여부를 알려주면 왕복을 줄이고
실제 출구 도달을 늘릴 수 있는가이다.

| 순서 | 조건 | 모델 입력 | 시작 조건 |
|---|---|---|---|
| 1 | MLP1 | 주변 벽 8개 + 출구까지 행·열 차이 2개 | 새 실행 승인 후 seed 0·1·2 |
| 2 | MLP2 | MLP1 + 상하좌우 이웃의 방문 여부 4개 | MLP1 세 seed 완료 및 아래 왕복 기준 충족 시, 같은 seed로 새로 초기화 |
| 참고 | 기존 CNN | 전체 지도·현재 위치·출구 | 기존 결과만 인용할 경우 관측 범위·방법 차이를 표시 |

MLP10과 MLP14 사이에서 바꾸는 주요 변수는 방문 정보의 제공 여부다. 입력층은
10→14로 넓어져 파라미터도 256개 늘어난다. 기존 CNN에서 MLP10으로 넘어갈 때는
모델 구조와 관측 범위가 함께 바뀐다. 이번 비교에서 두 변화의 효과를 분리할 수 없다.

## 입력과 정책

- 벽 비트 순서는 지도 기준 북·북동·동·남동·남·남서·서·북서다.
  벽 또는 지도 밖은 1, 통로는 0이다. 중심 칸은 입력에서 뺀다.
- 출구 차이는 `(출구 행 - 현재 행) / 9`, `(출구 열 - 현재 열) / 9`이다.
  행은 아래로, 열은 오른쪽으로 증가한다. 이 값은 좌표 차이이며 장애물을 돌아가는 실제 거리가 아니다.
- MLP14의 끝 4개는 북·동·남·서 이웃 칸을 **이번 에피소드에서 이미 밟았으면 1**,
  아니면 0이다. 벽·지도 밖은 0이다. 시작 칸을 방문한 상태로 초기화한다.
  이동이 끝나면 도착 칸을 기록한 뒤 다음 관측을 만든다. 충돌은 새 방문을 추가하지 않는다.
  매 에피소드에서 방문 기록을 초기화하고, 평가와 학습의 기록을 분리한다.
  replay에는 각 시점에 만든 관측을 값으로 저장한다.
- MLP는 입력 → Linear 64 → ReLU → Linear 64 → ReLU → Linear 4로 고정한다.
  파라미터는 MLP10 5,124개, MLP14 5,380개로 예상하며 실행 로그에서 실측한다.
  출력은 위·오른쪽·아래·왼쪽 점수다. 대각선 관측은 이동 행동을 추가하지 않는다.
- 두 조건 모두 합법 행동 mask 없이 시작한다. 방문 비트도 행동 금지 규칙으로 쓰지 않는다.
  같은 상태에 대한 greedy 동점은 기존 행동 인덱스 순으로 처리한다.
- 다른 지도에서 10개 관측이 같아도 더 먼 벽의 배치가 다를 수 있다.
  방문 비트는 국소 이력의 단서이며 전체 지도나 방문 순서 전체를 제공하지 않는다.

## 고정 설정과 예산 제안

기존 CUDA B의 원본 설정과 지도 manifest를 대조해 재사용한다.
10×10, 원래 훈련 16개와 개발 검증 8개, 기존 reward-v1(일반 이동 −.01, 충돌 −.05, 목표 +1),
에피소드 100행동, seed 0·1·2, seed당 20,000 훈련 환경 스텝,
Adam .001, gamma .99, replay 2,000, batch 32, learning starts 64,
train every 4, target hard copy 100, epsilon 1→.1/16,000을 고정한다.
실제 지도 순서와 해시를 보존한다. 최종 테스트 16개는 학습·평가·선택에 사용하지 않는다.

CUDA RTX 4060 worker 1개를 제안한다. 단계당 60,000스텝, 두 단계 합계 최대 120,000스텝을
계획한다. 재시도 기본 0회, 실패 시도도 사용량에 포함한다. seed soft 300초/hard 330초,
실행·집계·독립 검증 벽시계 최대 60분을 제안한다. 구현과 단위 검증 시간·스텝은 별도 기록한다.
CUDA 사용 불가 시 원인을 기록한다. 잔여 예산이 다음 seed의 상한을 감당하지 못하면 시작하지 않는다.
실행 승인 후 중복 프로세스 확인, Git 복구 지점, 실제 커밋과 변경 상태, config·지도·코드 해시를 기록한다.

## 14개 입력으로 넘어가는 기준

MLP10 마지막 체크포인트에서 기존 개발 검증 8개 × seed 3개, 총 24회 greedy 평가를 사용한다.
**24회 중 6회 이상이 두 칸 왕복 실패이고, 해당 실패가 2개 이상의 seed에서 나오면 MLP14를 실행한다.**
이 수치는 반복적으로 나타나는 문제에 후속 예산을 쓰기 위한 사전 운영 기준이다.

두 칸 왕복 실패는 목표에 도달하지 못하고 100행동으로 종료되며, 마지막 8개 이동이 서로 다른
두 칸 A↔B를 번갈아 오가는 경우다. 초반 재방문 후 빠져나온 사례와 제자리 충돌은 따로 센다.
기준 미충족이면 14개 단계는 미실행으로 기록한다. MLP10에 미완료 seed가 있으면 판단 보류로 기록한다.
기준을 넘지 않았더라도 전체 성공률이 낮다면 제자리 충돌·긴 순환·기타 실패의 수를 남긴다.

## 평가 및 검증

- 검증 greedy 평가는 0 및 매 500스텝에 실시한다. 주 비교는 20,000스텝 마지막 체크포인트다.
  그 전 최고값과 시점은 보조 지표로 기록한다. 훈련 greedy는 마지막 모델에서 훈련 16개로 평가한다.
  탐색이 포함된 훈련 return 원본·최근 20개 평균과 greedy 평가를 별도 표시한다.
- seed별 성공 수/분모, 평균·표본 SD·범위, 성공 경로 효율(최단 길이/실제 행동 수),
  왕복·제자리·기타 실패 수, 충돌 수, 환경/평가 스텝, 실제 optimizer 횟수·샘플 수·시간을 저장한다.
  왕복은 전체 24회 대비 및 실패 중 비율을 함께 기록한다. 왕복이 줄어도 성공이 늘지 않으면
  실패 양상 변화로 해석한다. 동일 seed·동일 지도에서 성공/실패 유형의 전환을 대조한다.
- 구현 후 벽 순서·경계·행열 차이, 방문 초기화와 이동/충돌 후 갱신, replay 관측 보존,
  MLP 4행동 출력, 종료/시간 제한 bootstrap, 평가 중 이력 분리를 검증한다.
- `studies/MLP-01/results/`에 실행 프로토콜, config/manifest와 run 연결, 예산 원장, 비교 JSON/CSV·그림·보고서,
  seed/지도별 위치·행동·관측·결과를 남긴다. 독립 담당은 체크포인트를 복원해 관측, 경로, 수치,
  조건 차이와 14개 진입 기준을 확인한다. 승인 상태와 comparison/protocol SHA-256을
  `review.json`, `verified_facts.json`에 남긴 뒤 조정자가 `scripts/commit_review.py`를 실행한다.

## 인스타 인계에 남길 장면

첫 소재는 **“눈앞 여덟 칸과 출구 방향만 알면 미로를 풀 수 있을까?”**다.
실제 체크포인트에서 뽑은 주변 3×3과 벽 비트 8개, 출구 차이 2개를 한 화면에 표시한다.

14개 실험을 했다면 두 번째 소재는 **“방금 밟은 칸을 알려주면 두 칸 왕복이 줄까?”**다.
같은 seed·같은 검증 지도의 마지막 정책을 나란히 재생한다. 왕복→성공 사례가 여러 개라면
seed 오름차순, 그 안에서 manifest 순서의 첫 사례를 고른다. 그런 사례가 없다면 같은 순서로
양쪽 모두 실패한 첫 사례를 사용하고, 그마저 없으면 양쪽의 결과 전환 집계로 보여준다.
대표 장면에는 seed·지도 해시·체크포인트 시점·행동 기록을 연결한다.

14개 실험을 하지 않았다면 진입 기준과 실제 실패 유형을 소재로 삼는다. 영상 한 장면과 전체
seed 결과는 같이 제시한다. 게시 문구는 독립 검증을 통과한 수치를 사용하며, 결과에 따라 작성한다.
