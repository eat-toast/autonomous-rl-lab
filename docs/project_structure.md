# 프로젝트 구조 계약

## 목적과 적용 범위

실험 주제별 자료를 `studies/<ID>/`에서 찾을 수 있게 한다. 계획, 전용 설정·스크립트,
실행 원본, 결과, 진단, 검증, 콘텐츠를 해당 실험 아래에 모은다.
공통으로 사용하는 구현·도구·규칙만 프로젝트 루트의 공통 폴더에 둔다.

이 문서는 현재 적용하는 배치 기준이다. 2026-11-08에 기존 실험 자료와 전용 도구를 study별로 이전했다.
연구 조건과 승인·예산은 [설계 계약](design.md), [작업 지침](../AGENTS.md), 개별 프로토콜을 따른다.
실험을 찾는 입구와 실행·검증 상태는 계속 [실험 목록](experiment_index.md)에서 관리한다.

## 공통 폴더

| 위치 | 소속 자료 |
|---|---|
| `studies/` | 실험 주제별 전용 자료 |
| `rl_lab/` | 여러 실험이 함께 사용하는 환경·모델·학습·평가 구현 |
| `scripts/` | 공통 실행 도구, 검증 커밋 도구, 공통 콘텐츠 생성 도구 |
| `tests/` | 공통 구현과 도구의 자동 테스트 |
| `configs/` | 여러 실험에 재사용하는 기본 설정과 실행 점검 설정 |
| `docs/` | 공통 연구 규칙, 구조 계약, 실험 목록·이름표, 콘텐츠 규격과 연재 기획 |
| `agents/` | 역할별 작업·인계 지침 |
| `assets/instagram/audio/` | 여러 게시물에서 재사용하는 공용 음원 원본·취득 메타데이터. 로컬 보존하며 Git 제외. 관리 목록은 docs/instagram_music_library.md |
| `.codex/` | 프로젝트의 Codex 설정과 에이전트 정의 |

루트에는 `AGENTS.md`, `README.md`, 의존성 목록과 Git 설정 파일 등 프로젝트 전체의 진입점만 둔다.
`scripts/`는 프로젝트 루트에 있으며, `studies/`와 같은 층이다.
실험별 실행·분석·제작 스크립트를 새로 만들 때는 해당 study의 `scripts/`에 둔다.
특정 실험을 위해 공통 구현을 수정하더라도 공통 모듈을 복제하지 않고 코드 커밋과 스냅샷으로 식별한다.

## 실험별 기본 구조

```text
studies/
└─ <ID>/
   ├─ README.md
   ├─ plan.md
   ├─ configs/
   ├─ scripts/
   ├─ tests/
   ├─ runs/
   │  └─ <run ID>/
   ├─ results/
   ├─ diagnostics/
   │  └─ <diagnosis ID>/
   │     ├─ results/
   │     └─ attempts/
   ├─ reviews/
   │  └─ snapshots/
   └─ exports/
      ├─ <게시물 ID>/
      └─ <게시물 ID>.zip
```

필요한 디렉터리만 만든다. 기존 계획서의 파일명을 일괄 변경할 필요는 없다.

- `README.md`: 연구 질문, 고유 ID, 기준 실험, 실행·검증 상태, 계획과 모든 자료의 위치를 연결한다.
- `plan.md`: 가설, 변경 변수, 고정 조건, 승인 범위, 예산, 평가·채택 기준을 기록한다.
- `configs/`, `scripts/`, `tests/`: 해당 실험에만 쓰는 설정·실행 및 분석 도구·전용 테스트를 둔다.
- `runs/`: run ID별 실제 설정, 코드 스냅샷, 미로, 로그, 체크포인트와 상태를 보존한다.
  실패 실행도 보존하며 기존 run을 덮어쓰지 않는다.
- `results/`: 집계 보고서, comparison, protocol, ledger 등 실행 및 비교의 원본 기록을 둔다.
- `diagnostics/`: 해당 실험의 실패 원인·속도·경로 분석과 진단 실패·중간 시도를 둔다.
- `reviews/`: 독립 검증 보고서와 검증 자료 보존본을 모으는 목표 위치다.
  도구가 요구하는 `results/review.json`, `results/verified_facts.json` 등은 도구 전환 전까지 유지한다.
- `exports/`: 해당 실험을 근거로 한 게시물의 작업 자료와 최종 ZIP을 둔다.
  게시·검수 완료 후 회차별 정식 ZIP 하나만 남기는 기존 보존 규칙을 적용한다.

ID는 [실험 이름과 원본 ID](experiment_names.md)를 따른다. 폴더의 ID와 표시 이름을 혼동하지 않는다.
이미 등록된 ID와 run ID는 유지한다. 같은 실험의 조건·seed를 서로 다른 주제로 재분류하지 않는다.
다른 실험의 대조군이나 공통 미로는 원본 경로와 해시로 연결하고 원본을 중복 복제하지 않는다.
여러 실험을 다루는 게시물은 연재 제작 지시서에 주관 study와 모든 근거 study를 기록하고,
주관 study의 `exports/` 한 곳에서 관리한다.

연재 기획은 김작가가 `docs/series/README.md`와 `docs/series/episodes/`에서만 관리한다.
제작·게시·보관 상태 및 정식 파일 위치의 입구는 인스타그램 담당의
`docs/instagram_publications.md`다. 실제 파일·정식 ZIP과 상세 제작·검수 기록은
인스타그램 담당이 주관 study의 `exports/`에서 관리하며 김작가는 이를 복제·복원·정리하지 않는다.

## 현재 배치와 과거 기록

루트의 `runs/`, `diagnostics/`, `review_snapshots/`, `exports/`는 소속 study 아래로 이전했다.
실험 전용 스크립트·설정·테스트도 해당 study로 이전했다. 공통 테스트 명령은 study별 테스트를 함께 찾는다.

- 모든 경로 대응은 [이전표](path_migrations.json), study별 자료 안내는 각 `README.md`에서 확인한다.
- 원본 JSON·로그·검증 스냅샷·게시물 패키지 내부의 과거 경로와 해시는 수정하지 않는다.
- `rl_lab/paths.py`는 과거 경로를 현재 위치로 해석한다. 새로운 자료는 현재 경로를 기록한다.
- 검증 원본인 `review.json`과 `verified_facts.json`은 해시 계약을 유지하기 위해 `results/`에 보존한다.
  `reviews/snapshots/`에는 해당 원본의 불변 보존본을 둔다. 검증 커밋 도구는 이전한 보존본을 재사용한다.
- 여러 실험의 비교에 사용한 CPU·GPU 속도 측정은 기준 CPU B가 속한 CNN-02의 진단에 보존했다.
- MLP3의 원본 묶음 ID `MLP-02`와 표시 이름용 `MLP-03`은 기존 대응을 유지한다.
- 게시물의 제작 중 폴더와 기존 ZIP도 그대로 이전했다. 정리는 게시·검수 완료 확인 뒤 별도로 수행한다.
- 로컬 이력용 제작 스크립트는 보존하되, 새 콘텐츠는 독립 검증과 커밋 게이트를 사용하는 도구로 제작한다.

## 이전 절차와 보존

1. 실행 중인 학습·평가·제작과 기존 미커밋 변경을 확인한다. 실행 중인 코드·설정·원본 경로는 변경하지 않는다.
2. 소속 study와 이전 전후 경로표를 README에 기록하고 Git 복구 지점을 확보한다.
   원본 run·체크포인트·검증 파일의 파일 수와 해시를 기록한다.
3. 파일을 이동할 때 실행기·분석기·검증 커밋·콘텐츠 도구·테스트·문서 링크·Git 추적 규칙을 함께 수정한다.
   승인된 원본 JSON, 로그, 스냅샷 내부의 과거 경로는 기록이므로 치환하지 않는다.
   과거 경로는 README의 경로표나 도구의 경로 해석으로 연결한다.
4. 이동 후 파일 수와 해시, 문서 링크, 관련 도구와 검증 절차를 확인한다.
   경로 확인을 위해 학습을 재실행하거나 최종 테스트를 사용하지 않는다.
5. 실험 목록의 같은 항목과 관련 지침을 갱신한다. 실패·중간 시도와 복구 출처를 보존한다.

Git에는 계획, 설정, 코드, 보고서와 검증 보존본을 추적한다.
체크포인트, 대용량 실행 산출물, 콘텐츠 작업물은 기존처럼 로컬에 보존한다.
`.gitignore`는 실행 원본·결과·콘텐츠를 제외하고, study의 문서·전용 코드·설정·테스트·검증 보존본을 허용한다.
실험 폴더 전체를 무조건 Git에 추가하지 않는다.

이 문서는 구조의 기준이며 자동 폴더 생성기는 아니다. 구조를 바꿀 때는 이 문서와 실제 저장 도구를
함께 갱신하고 [AGENTS.md](../AGENTS.md)의 연결을 유지한다.
