# MLP-03-벽방향제외

원본 묶음 ID는 `MLP-02`다. MLP3의 대조군은 MLP2(원본 조건 `MLP14`)다.

2026-11-07에 사용자가 아래 계획과 예산으로 실행을 승인했다. 실행·검증 상태는 [실험 목록](experiment_index.md)에 기록한다.

MLP2의 마지막 체크포인트는 개발 검증에서 seed별 7/8·5/8·7/8, 총 19/24에 성공했다(평균 79.2%, 표본 SD 14.4%p). 남은 실패는 두 칸 왕복 3건과 제자리 충돌 2건이었다. 벽이나 격자 밖으로 향하는 행동을 후보에서 제외하면 제자리 충돌을 막을 수 있다. 성공까지 늘어나는지, 충돌 실패가 왕복 등 다른 실패로 바뀌는지는 실험으로 확인한다.

## 비교와 판정

- 대조군은 독립 검증을 통과한 MLP2 seed 0·1·2, 마지막 20,000스텝 체크포인트다. 후보는 같은 seed로 새로 초기화한다.
- 바꾸는 변수는 벽·격자 밖을 향하는 행동의 제외 여부다. MLP2가 이미 관측하는 북·동·남·서 벽 비트를 사용한다. 후보에서는 탐색과 greedy 선택, DQN의 다음 상태 최대 Q값에 같은 규칙을 적용한다. 방문한 칸으로 돌아가는 행동은 허용한다. 최종 상태 bootstrap 및 시간 제한 처리는 기존과 동일하다.
- MLP2 입력과 모델 구조, 보상, 훈련 지도 16개와 개발 검증 지도 8개의 원본과 순서, seed, 에피소드 100행동, CUDA 장치, 탐색 일정과 기타 학습 설정을 MLP-01과 동일하게 유지한다. 최종 테스트는 사용하지 않는다.
- MLP-01과 동일하게 0 및 500스텝마다 개발 검증을 수행하고, 마지막 20,000스텝의 greedy 성공률을 주 지표로 사용한다. 중간 최고값은 보조 지표다. seed별 성공 수와 분모, 평균·표본 SD·범위, 같은 seed·미로에서의 성공/실패 전환과 실패 유형, 충돌 수, 성공 경로 효율을 남긴다. 훈련 탐색 return과 마지막 훈련 greedy 성공률을 분리한다.
- 24회 중 21회 이상 성공하고 어느 seed도 기준보다 낮지 않으면 후속 후보로 채택한다. 미달이면 실제 차이와 실패 전환을 기록한다. 3개 seed와 기존 개발 검증 지도에 대한 운영 기준으로, 새 미로에 대한 일반화 주장은 하지 않는다. 미완료 seed가 있으면 채택 판정을 보류한다.

## 예산과 검증

- RTX 4060 CUDA worker 1개, seed당 20,000스텝, 신규 훈련 최대 60,000스텝. seed당 soft 300초/hard 330초, 전체 실행·집계·검증 최대 30분, 재시도 0회. 실패 시도도 예산에 포함한다. CUDA 불가 또는 다음 seed를 완료할 예산이 부족하면 중단 상태를 기록한다.
- 실행 승인 후 중복 작업 확인, Git 복구 지점 확보, 실제 코드 커밋과 변경 상태 및 설정·지도·코드 해시를 기록한다. 기존 run은 보존하고 새 결과는 `studies/MLP-02/results/`에 남긴다.
- 경계·벽 제외, 막다른 길에서의 되돌아가기, 탐색/greedy/target의 일관성과 종료·시간 제한 처리를 확인한다. 검증 담당은 원본과 복원 체크포인트로 성공 및 실패 전환을 대조하고 `review.json`, `verified_facts.json`을 작성한다. 콘텐츠 인계 전에 `scripts/commit_review.py`로 검증 기록을 보존한다.
