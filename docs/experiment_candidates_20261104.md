## 먼저 구분할 것: 버퍼의 초기 경험과 모델에 남은 학습

현재 replay는 capacity 2,000의 FIFO ring이다. 새 경험이 가득 찬 버퍼에 들어오면 가장 오래된
경험을 덮어쓴다. 따라서 **20,000스텝 학습 종료 시 처음 2,000스텝의 경험은 이미 버퍼에 없다.**
버퍼에는 최신 2,000개 전이만 남는다. “초기 데이터를 지우기”는 이미 일어나는 자동 교체와,
학습 도중 현재 버퍼를 한 번 비우는 개입을 구분해야 한다.

- 버퍼 clear는 현재 저장된 경험을 지운다. 신경망 가중치, 타깃 네트워크, Adam 상태는 그대로다.
- 성공 경험과 드물게 방문한 상태도 함께 잃는다. 오래된 경험이 항상 나쁜 경험은 아니다.
- 가중치에 남은 초기 학습의 영향은 버퍼 clear만으로 지워지지 않는다.
- primacy bias가 이 프로젝트 실패의 원인이라고 확인되지 않았다. **버퍼를 비우면 primacy bias가
  해결된다고 단정하지 않는다.** 해당 연구의 에이전트 일부 reset과 replay clear는 다른 개입이다.
  [Primacy bias 원 논문](https://arxiv.org/abs/2205.07802)
- capacity를 늘리기, 버퍼 비우기, 성공 경험 유지, 가중치 reset, optimizer reset은 각각 다른 실험이다.

우선순위는 효과가 보장된 순위가 아니라 **현재 관찰에 대한 진단력·비용·구현 부담** 기준이다.
P0는 작은 진단, P1은 우선 비교할 후보, P2는 후속 후보, P3는 추가 구현·해석 부담이 큰 후보다.
`설정`은 현 코드의 설정값으로 가능, `코드`는 구현·테스트 필요, `도구`는 별도 평가/로깅 도구 필요를 뜻한다.

|---|---|---|---|---|---|

PER는 성공 전이만 선택하는 기법이 아니다. TD 오차 기반 우선순위와 importance sampling 보정을
정확히 구현해야 한다. 성공 유지·성공 샘플링도 PER와 다른 후보로 기록한다.
[PER 원 논문](https://arxiv.org/abs/1511.05952)

### 버퍼 clear의 권장 대조 설계

초기 비교에서는 기존 학습을 이어가는 임의의 checkpoint 대신 같은 seed에서 두 조건을 처음부터
학습한다. t=10,000까지 설정을 같게 하고, 그 시점의 가중치·설정·버퍼 요약을 기록한다.

| 조건 | t=10,000에서 하는 일 | 이후 공통 처리 |
|---|---|---|
| 대조군 | 버퍼 유지 | 256 환경 스텝 동안 경험만 수집하고 optimizer 갱신은 일시 정지 |
| 개입군 | 버퍼 1회 clear | 같은 256스텝 수집/갱신 정지 후 학습 재개 |

두 조건의 모델·optimizer 상태는 reset하지 않고, epsilon 스케줄도 계속 진행한다.
샘플러 RNG를 임의로 초기 seed로 되돌리지 않는다. 같은 총 20,000 환경 스텝과 같은 optimizer
갱신 횟수를 사용한다. 위 예에서는 10,001~10,256 구간의 64회 갱신을 양쪽에서 제외하므로
기존 4,985회 대신 양쪽 모두 4,921회다. 구현 시 실제 카운터로 확인한다.

이 공통 pause 자체도 원래 B와 다른 실행 방식이다. 따라서 **clear의 효과는 pause가 같은
대조군과 비교**하고, 기존 B에 대한 차이를 clear 하나의 효과로 부르지 않는다.
실험 시점을 결과를 본 뒤 유리하게 고르지 말고 사전에 고정한다.

추가 로그: 전이 생성 스텝/나이, 버퍼의 성공 전이 수·비율, 지도별 점유율, 샘플된 전이의 나이와
성공 비율, clear 전후 return·충돌·훈련/검증 성공률. 가중치가 그대로라는 사실과 버퍼 clear
직후 count=0, 충분히 수집한 뒤 샘플링 재개를 테스트해야 한다.

## 2. 탐색과 평가 정책

| 후보 | 현재 → 구체적 변경 예 | 겨냥한 실패·가설 | 손해·trade-off | 구현 | 우선 |
|---|---|---|---|---|---|
| 작은 epsilon으로 평가 | 같은 checkpoint에서 epsilon 0 → 0.02/0.05. 반복 평가 RNG를 사전 고정 | 잘못된 greedy 순환에 갇혀서 실패하는지 | 우연한 탈출·도착도 포함됨. 원래 greedy 성능이 좋아졌다고 소개하면 안 됨 | 도구 | P0, 재학습 없음 |
| 최종 탐색률 증가 | epsilon_end 0.1 → 0.2, 감소 기간 16k 유지 | 후반에 새로운 경로를 충분히 찾는지 | 이미 아는 좋은 행동도 더 자주 방해함. 훈련 return이 낮아질 수 있음 | 설정 | P2 |
| 탐색 스케줄 형태 | 선형 감소 → 초기 plateau 뒤 감소 등 한 가지 사전 고정 형태 | 좋은 경험을 얻기 전에 탐색이 줄어드는지 | 총 무작위 행동량이 달라짐. 다른 스케줄과 의미를 맞춰 기록해야 함 | 코드 | P2 |
| 방문 상태 반복 시 탐색 | 학습 정책의 반복 감지 시에만 확률적으로 다른 행동 | 같은 상태의 잘못된 행동을 반복하는지 | 이력 기반 외부 제어가 추가됨. 학습된 순수 greedy 정책과 별도 방법이며 정상적인 되돌아가기도 방해할 수 있음 | 코드 | P3 |
| Noisy Networks | epsilon-greedy → 학습 가능한 파라미터 노이즈 탐색 | 독립 무작위 행동보다 일관된 탐색이 필요한지 | 네트워크·탐색 방식이 바뀌고 분산도 달라짐. 첫 원인 진단으로는 복잡함 | 코드 | P3 |

작은 epsilon 진단은 동일 모델을 훈련/검증에서 평가하고, 무작위 평가 RNG별 성공률·행동 수를
보고한다. epsilon=0의 같은 결정적 평가를 여러 번 반복해 표본 수를 부풀리지 않는다.
성공한 평가 한 번만 골라 대표 성능으로 쓰지 않는다. 이 진단만으로 학습 능력이나 일반화가
해결됐다고 결론내리지 않는다.

## 3. 보상 전파와 DQN 개선

아래 후보는 환경이 주는 보상 값은 유지하면서 학습 목표·샘플링·행동 선택을 바꾸는 연구다.

| 후보 | 현재 → 구체적 변경 예 | 겨냥한 실패·가설 | 손해·trade-off | 구현 | 우선 |
|---|---|---|---|---|---|
| n-step return | 1-step TD → 3-step, 이후 별도 5-step 비교 | 드문 목표 보상을 앞선 행동에 더 빨리 전달해야 하는지 | 분산·off-policy 영향 증가. episode 경계·truncation 처리 구현 필요 | 코드 | P1 |
| Double DQN | target-network max → online이 선택하고 target이 평가 | max 연산으로 잘못된 행동 가치가 과대평가되는지 | 탐색·지도 다양성 문제를 직접 해결하지는 않음. 현재 과대평가가 원인인지는 아직 미검증 | 코드 | P1~P2 |
| 불가능 행동 mask | 4행동 모두 허용 → 벽/경계로 향하는 행동 제외 | 같은 벽에 충돌하며 제자리인 실패를 줄일 수 있는지 | 지도에서 합법 행동을 계산하는 사전 지식 추가. 빈 공간 왕복은 해결하지 못함 | 코드 | P1~P2, 방법 차이 명시 |
| 타깃 갱신 주기 | 100 → 500 환경 스텝 | bootstrap 목표가 너무 자주 바뀌는지 | 더 안정적일 수도 있지만 새 가치를 늦게 반영할 수도 있음 | 설정 | P2 |
| Soft target update | hard copy → 작은 tau의 매 갱신 보간 | 갑작스러운 타깃 변경이 흔들림을 만드는지 | tau·적용 주기 정의 필요. hard update 주기와 동시에 튜닝하지 않음 | 코드 | P3 |
| Dueling DQN | 단일 Q head → value/advantage 분리 | 상태 가치와 행동 차이를 나누는 표현이 유리한지 | 파라미터 수·구조가 달라짐. 불공정한 모델 크기 차이를 기록해야 함 | 코드 | P2 |
| Distributional DQN | Q 기대값 하나 → 보상 분포 예측 | 기대값만 학습하는 표현이 병목인지 | 분포 support와 출력 구조 등 추가 설정 필요. 단순 원인 진단을 넘어섬 | 코드 | P3 |
| Rainbow 결합 | 개별 기법 비교 후 조합 | 각각 유용했던 개선이 함께 작동하는지 | 여러 변수가 동시에 바뀌어 원인을 분리하기 어려움. 초기 디버깅용으로 사용하지 않음 | 코드 | P3, 개별 비교 후 |

Double DQN은 행동의 선택과 가치 평가를 분리하는 후보다.
[Double DQN 원 논문](https://arxiv.org/abs/1509.06461)
여러 개선의 조합과 구성요소 분석은 별도 단계로 구분한다.
[Rainbow 원 논문](https://arxiv.org/abs/1710.02298)

n-step 구현은 에피소드 reset을 가로질러 다른 미로의 보상을 합치지 않아야 한다. 실제 누적 길이
k에 맞는 gamma^k, 목표 도달 mask, 시간 제한의 마지막 실제 관측 bootstrap을 테스트한다.
이것은 환경 보상 함수를 바꾸는 reward shaping과 다른 개입이다.

mask는 탐색 시 무작위 행동, greedy 선택, 다음 상태의 TD target 선택에서 일관되게 적용한다.
terminal 또는 합법 행동이 없는 경우에도 무한대·NaN target이 생기지 않도록 테스트한다.
기존 보상/관측 차원은 그대로여도 **사전 지식을 추가한 행동 제약 방식**임을 비교표에 명시한다.

## 4. 환경과 일반화

| 후보 | 현재 → 구체적 변경 예 | 겨냥한 실패·가설 | 손해·trade-off | 구현 | 우선 |
|---|---|---|---|---|---|
| 단일 훈련 미로 진단 | 고정 pool 16개 → 기존 훈련 미로 1개 | 작은 한 문제 자체도 안정적으로 학습하는지 | 일반화 비교가 아니라 최적화/학습 가능성 진단. 성공해도 새 지도 능력을 증명하지 않음 | 설정 또는 진단 도구 | P0~P1 |
| 훈련 미로 다양성 | pool 16 → 64개, 같은 총 20k스텝 | 익숙한 지도에만 맞춘 정책인지 | 지도당 경험이 줄어드는 trade-off. 같은 예산에서의 다양성 효과로 해석 | 설정, 검증 pool 고정 확인 | P1 |
| 새 훈련 미로 계속 생성 | 유한 pool → 훈련 episode마다 새 도달 가능한 미로 | 지도를 암기하는 대신 공통 규칙을 배울 수 있는지 | 한 지도 반복 학습 기회 감소, 생성 비용 증가. 생성 seed·분포 로그 필요 | 코드 | P2 |
| 같은 크기의 쉬운 미로 curriculum | 10×10 고정, 초기 밀도 0.05 → 목표 밀도 0.20 | 먼저 성공 경험을 만들면 학습이 나아지는지 | 훈련 분포·난이도가 시간에 따라 달라짐. 같은 평가 미로에서 비교해야 함 | 코드 | P2 |
| 훈련 시작 위치 분포 | 항상 (0,0) → 목표에 가까운 훈련 시작점부터 확대, 검증 시작점 유지 | 목표 근처 보상을 먼저 경험해 전파할 수 있는지 | 환경 과제의 훈련 분포 변경. 시작점별 도달 가능성·최단 경로 재계산 필요 | 코드 | P2~P3 |
| 훈련 episode 제한 확대 | 훈련 100 → 200행동, 검증은 100 유지 | 탐색 중 목표에 닿을 기회가 부족한지 | 같은 스텝에서 episode/미로 전환 수 감소. greedy 순환은 시간만 늘려도 탈출하지 않음 | 코드: 현재 train/eval max_steps 분리 필요 | P2~P3 |
| 개발 검증 표본 확대 | 기존 8개 외에 사전 고정한 추가 개발 세트에서 기존 모델부터 재평가 | 작은 평가 표본 때문에 선택이 흔들리는지 | 검증 비용 증가. 새 점수를 보고 계속 세트를 고르면 다시 선택 편향 발생 | 도구·자료 고정 | P1, 성능 추정 진단 |

훈련 pool을 늘릴 때 현재 `make_splits`를 다시 호출했다는 이유만으로 기존 검증 지도가 같다고
가정하지 않는다. 기존 검증의 실제 지도와 해시를 고정하고 겹침을 확인한다. 최종 테스트는 열어
개선 방향을 고르는 데 사용하지 않는다. 단일 지도 진단에서도 검증/테스트 지도를 훈련에 넣지 않는다.

## 5. 모델과 최적화

| 후보 | 현재 → 구체적 변경 예 | 겨냥한 실패·가설 | 손해·trade-off | 구현 | 우선 |
|---|---|---|---|---|---|
| Batch 크기 | 32 → 64 | gradient 추정의 변동을 줄여야 하는지 | 같은 갱신 횟수에서도 샘플 처리량·계산량 증가. 더 큰 배치가 반드시 좋지는 않음 | 설정 | P2 |
| 학습/경험 비율 | train_every 4 → 2 또는 1 | 수집한 경험을 덜 학습하는지 | 같은 환경 스텝에서 optimizer 갱신·재사용·계산량이 증가. 과도한 replay 학습 가능 | 설정 | P2 |
| 학습률 추가 후보 | 기준 0.001 → 사전 고정한 0.0005 등 한 값 | 갱신 크기와 주어진 예산이 맞지 않는지 | 기존 0.0003 결과가 낮았으므로 무작정 낮추는 처방은 근거 부족. 끝없는 탐색 금지 | 설정 | P3 |
| Gradient clipping | norm 10 → 5 | 드문 큰 gradient가 학습을 흔드는지 | 필요한 갱신도 줄일 수 있음. 먼저 norm·clip 비율 로깅 필요 | 설정 + 진단 로그 | P3 |
| CNN 특징 채널/깊이 | 16→32 채널 2층 → 32→64 또는 3층 중 하나 | 지형 특징의 표현 방식이 병목인지 | 파라미터·FLOPs·최적화 난이도 증가. FC 폭 실험과 다른 개입 | 코드 | P2~P3 |
| FC 너비 추가 확대 | 64 → 256 | 더 큰 출력 전 표현이 필요한지 | 128이 이번 예산에서 개선되지 않았음. 암기·계산 비용만 늘 수 있어 우선순위 낮음 | 설정 | P3 |
| 가중치 정규화 | weight decay 없음 → 사전 고정한 작은 값 | 훈련/검증 격차를 줄일 수 있는지 | 학습 자체가 부족한 seed에는 더 불리할 수 있음. 초기값·옵티마이저 조건 기록 | 코드 | P3 |
| 모델 일부 reset | 정해진 시점에 FC만 재초기화하고 replay 유지 | 초기 학습의 영향이 새 경험 적응을 방해하는지 | 이미 배운 정책 손실. 타깃/optimizer 상태 처리 규칙이 필요하며 replay clear와 다른 연구 | 코드 | P3, primacy 가설 별도 검증 |
| Optimizer 상태 reset | 가중치와 replay는 유지하고 Adam 상태만 초기화 | 과거 optimizer 누적 상태가 적응에 영향을 주는지 | 갑작스러운 업데이트 변화, 불안정 가능. 모델 reset/clear와 동시에 하지 않음 | 코드 | P3 |

모든 보상/성공률 그래프와 함께 실제 optimizer 갱신 횟수, 배치에서 처리한 총 전이 수,
시간·메모리·파라미터 수를 기록한다. 현재 20k·warmup 64·train_every 4는 4,985회 갱신이다.
warmup이나 train_every를 바꾸면 이 수가 달라진다. “같은 환경 스텝”을 “같은 학습 계산량”으로
소개하지 않는다. 갱신 횟수까지 맞추는 별도 비교는 조정 방식 자체를 사전에 정의해야 한다.

## 6. 현재 State·Reward 고정 연구 밖의 별도 후보

다음은 기법 목록에는 포함하되 **현재 기준 실험에 곧바로 섞지 않는 후속 연구**다.

| 후보 | 변경 예 | 연구가 달라지는 지점 | 손해·주의 | 구현/범위 |
|---|---|---|---|---|
| Reward shaping | 목표까지 진행한 정도를 추가 보상으로 제공 | 현재 고정 reward-v1 변경 | 편리한 보상 신호가 원래 과제를 다른 문제로 바꿀 수 있음. 추가 거리 정보의 역할을 명시 | 코드·별도 보상 연구 |
| HER | 실패 경로에서 도달한 위치를 가상 목표로 relabel | 목표 분포·학습 상태/보상 의미 변경 | 같은 입력 차원을 유지하더라도 원래 목표 학습 자료와 다른 데이터가 됨 | 코드·별도 목표조건 연구 |
| 방문 이력/좌표 입력 추가 | 방문 횟수 채널, 상대 좌표 벡터 추가 | 현재 고정 observation-v1 변경 | 정보량·네트워크가 함께 바뀌면 순수 알고리즘 비교가 아님 | 코드·별도 State 연구 |
| 반복 방문 페널티 | 같은 칸 재방문에 추가 음수 보상 | 고정 보상 변경, 이력 의존성 추가 | 정당한 되돌아가기까지 벌할 수 있으며 상태의 Markov 가정을 다시 검토해야 함 | 코드·별도 환경/보상 연구 |
| A* 시범 경험 사전 적재 | 훈련 미로의 전문가 경로 일부를 replay에 삽입 | 순수 자기 탐색과 전문가 보조 학습의 차이 | 전문가 데이터/계산 비용을 숨기면 sample efficiency 비교가 불공정함. 검증/테스트 시범은 금지 | 코드·별도 전문가 보조 연구 |

## 7. 공통 재현·비교 계약

새 실행 전 실험 담당이 계획을 만들고, 결과 담당이 수치와 범위를 검증한 뒤 게시물 담당에게 넘긴다.
이 목록은 새 실행 승인이나 무제한 파라미터 탐색으로 해석하지 않는다.

1. **한 주요 변수**: 기준 B에서 하나의 replay/탐색/학습 방법을 바꾼다. 유망한 후보를 조합하는 일은
   각 기법 비교 뒤 별도 단계로 둔다. 코드상 필수 부수 설정은 모두 공개한다.
2. **독립 학습 seed**: 기본 0·1·2를 사용하고 같은 비교 조건에 대응시킨다. 평가 미로 수와 학습 seed
   수를 혼동하지 않는다. 작은 차이는 5개 이상 seed에서 확인할 후속 후보로만 둔다.
3. **같은 자료**: 같은 훈련/개발 검증 지도를 쓰되, 지도 다양성 자체가 실험 변수일 때만 훈련 pool을
   바꾼다. 검증의 실제 격자·해시는 유지하고 훈련 자료와의 겹침을 검사한다. 최종 테스트 미사용.
4. **같은 평가**: 동일한 100행동 제한과 사전 평가 주기를 사용한다. 마지막 모델과 중간 최고 모델,
   greedy와 stochastic 평가를 각각 구분한다. mask를 쓰는 방법은 행동 제약 추가를 명시한다.
5. **예산 기록**: 예를 들어 학습 조건당 3×20k=60k 환경 스텝으로 시작할 수 있지만 실행 전에 시간·
   메모리·optimizer 갱신·재시도 예산까지 정한다. 실패 시도의 실제 사용량도 포함한다.
6. **원본 로그**: episode별 return·성공·행동·충돌, 탐색률, loss, Q/TD 진단, seed별 검증 기록,
   replay 성공/나이/지도 분포, 갱신 횟수, 시간·메모리·Git/config/data 식별 정보를 보존한다.
7. **단위 테스트**: clear 후 샘플 수, 성공 유지, PER 확률/가중치, n-step 경계, mask와 target,
   Double DQN 선택·평가 분리 등 해당 기법의 오류가 성능처럼 보이지 않도록 검증한다.
8. **실패도 결과**: 잘된 seed만 고르거나 불리한 시점을 지우지 않는다. 원본·복구 출처를 남긴다.
   여러 개발 검증 결과로 선택한 조건은 최종 성능 확정이 아니라 잠정 선택으로 기록한다.

## 8. 실제로 고른다면 권장하는 묶음

전부 한 번에 실행하기보다 질문별로 고른다.

- **“지금 실패가 순환 탈출 문제인가?”** 같은 checkpoint의 작은 epsilon 평가 진단. 학습 변경 없이 확인한다.
- **“버퍼가 원인인가?”** FIFO 2k 대 10k, 그다음 공통 pause를 둔 clear 대 유지. clear와 용량 확대를 동시에 하지 않는다.
- **“성공 경험을 충분히 활용하는가?”** PER 또는 성공 경험 유지 중 하나를 우선 선택하고, 이후 n-step 3과 별도로 비교한다.
- **“Q 선택이 잘못되는가?”** Double DQN 또는 합법 행동 mask를 각각 별도 방법으로 비교한다.
- **“익숙한 지도만 푸는가?”** 훈련 pool 16 대 64. 한 지도도 못 배우는 seed가 많다면 단일 훈련 지도 진단을 먼저 한다.

현재 결과만으로 위 후보 중 어느 것이 성공할지는 알 수 없다. 각 후보는 원인 가설을 분리하거나
개선 여부를 확인하기 위한 실험이며, 효과를 미리 보장하는 처방이 아니다.
