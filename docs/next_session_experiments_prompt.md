## 실행할 후보와 순서

다음은 모두 이번 범위다. 첫 묶음만 실행하고 나머지를 단순 제안으로 남기지 마. 각 세부 설정은 아래 값을 기본으로 사전 고정하고 구현상 필요한 정의를 후속 프로토콜에 적어줘.

### 1묶음: 학습 방법 비교

0. **CUDA B 기준군**: 원래 B 설정 그대로, replay clear/pause 없음.
1. **성공 경험 유지**: 총 버퍼 용량은 2,000 유지. 성공 에피소드의 전이를 보관하는 FIFO 200슬롯과 일반 FIFO 1,800슬롯. 일반 FIFO에는 모든 전이를 넣고, 성공 저장소에는 성공 에피소드의 전체 전이를 추가한다. 배치는 채워진 두 저장소의 슬롯을 합쳐 균등 추출하고, 별도의 성공 배치 할당은 추가하지 않는다. 중복 보관되는 성공 전이, 저장소별 점유율·실제 성공 샘플 비율을 기록한다. 이 정의의 효과는 용량 배분·중복 보관을 포함한 성공 경험 유지 방식 전체의 효과로 해석한다.
2. **PER**: 총 capacity 2,000, proportional priority, alpha .6, beta .4→1.0을 20k 환경 스텝에 걸쳐 선형 증가. priority epsilon 1e-6, 새 전이는 현재 최대 priority(비어 있으면 1), importance weight는 배치 최대값으로 정규화. 성공 경험 유지와 섞지 않는다.
3. **3-step DQN**: n=3, episode 경계를 넘지 않고 실제 누적 길이 k에 맞게 gamma^k를 적용. 종료·시간 제한 bootstrap을 정확히 처리한다. 마지막 미완료 구간의 flush 규칙과 실제 replay 삽입 수를 기록한다.
4. **Double DQN**: online이 다음 행동을 선택하고 target이 그 행동의 가치를 평가. 나머지는 기준과 동일.
5. **합법 행동 mask DQN**: 현재 지도의 벽·경계로 가는 행동을 탐색·greedy 선택·TD target 모두에서 제외. 사전 지식을 추가한 별도 방법임을 명시하고 기본 DQN과 동등한 정보 조건이라고 주장하지 않는다.

### 2묶음: 일반화와 학습 설정 비교

6. **훈련 지도 다양성**: train pool 16→64, 총 환경 스텝은 동일. 검증 지도는 기존 8개 그대로.
7. **배치 확대**: batch 32→64. optimizer 갱신 일정은 유지. 계산량·샘플 처리량 증가를 기록한다.
8. **학습 빈도 증가**: train_every 4→2. 실제 optimizer 갱신·샘플 처리량 증가를 기록한다.
9. **타깃 갱신 간격 확대**: hard target update 100→500 환경 스텝.

이번에는 보상 shaping, 입력 채널 추가, HER, A* 시범 학습, 모델 추가 확대, 기법 결합, 최종 테스트는 하지 마. 단일 지도 재실험도 추가하지 마.
