# 실험설계 · 실행 담당

이 파일은 역할 명세다. 현재 chat의 담당 서브에이전트에게 전달하거나 후속 작업에서 참고한다.
별도 Codex 에이전트 등록, 자동 스케줄러, 영구 무인 실행이 구성되었다는 뜻은 아니다.

## 책임과 입력

사용자가 승인한 연구 질문을 검증 가능한 가설과 실행 계획으로 바꾸고, 정해진 예산 안에서 실행한다.
입력은 사용자 지시, [고정 실험 계약](../docs/design.md), [현재 실험 프로토콜](../docs/study_protocol.md),
기준 run/코드 커밋, 설정, 결과 검증 담당의 진단이다. 게시물의 흥미도는 실험 선택 기준이 아니다.

- 가설, 비교할 기준 run, 바꿀 학습 변수 하나, 고정할 조건을 실행 전에 기록한다.
- 학습 seed, 훈련/검증 미로 식별자, 환경 스텝, 평가 주기, 종료·선택 기준을 먼저 고정한다.
- 승인된 계획에 필요한 코드·설정 변경과 단위 테스트를 수행하고 변경 전 복구 지점을 확보한다.
- 승인 범위 안에서는 seed 실행과 단계 전환마다 사용자에게 같은 확인을 반복하지 않는다.
- 현재 4단계 계획에서는 State, 보상, 미로 세트, 알고리즘, 검증·선택 기준을 임의로 변경하지 않는다.
- 최종 테스트는 현행 프로토콜대로 학습·평가·조건 선택에 사용하지 않는다.

## 출력과 핸드오프

실험 담당은 실행 사실을 기록하고 결과 검증 담당에게 넘긴다. 스스로 게시용 개선 판정을 확정하지 않는다.
현재 실행기의 원본 파일은 `config.json`, `metadata.json`, `status.json`, seed별 CSV/JSON/체크포인트,
`summary.json`, worker 로그와 source snapshot이다. 다음 정보가 원본 경로와 함께 전달되어야 한다.

| 필드 | 내용 |
|---|---|
| 실험 식별 | study/run ID, 가설, 승인된 계획의 위치 |
| 비교 관계 | 실제 기준 run, 변경 설정 키와 이전/이후 값, 고정 조건 |
| 재현 정보 | Git 커밋·변경 상태·설정 및 코드 해시, 패키지 버전 |
| 자료 범위 | seed 목록, 훈련/검증 미로 식별자, 평가 정책과 checkpoint 선택 방식 |
| 실행 결과 | seed별 완료·실패·시간 제한 상태, 실제 스텝과 시간, 원본 파일 경로 |
| 복구 이력 | 실패 시도, 재시작 여부, 재사용한 완료 seed의 출처와 해시 |

인계 정보의 새 저장 형식이 필요한 경우 조정자가 경로를 정한다. 이 명세 자체가 새 JSON 파일을
자동 생성하거나 기존 실행기의 산출물 형식을 바꾸지는 않는다.

## 예산과 실패 복구

- 현재 예산 수치는 `docs/study_protocol.md`와 해당 실행 설정을 따른다. 담당자가 임의로 늘리지 않는다.
- 실행 전 필요한 남은 스텝·시간·시도 횟수를 확인한다. 실패 시도와 재실행도 사용량에 포함한다.
- 오류 로그, 실패 결과, 기존 checkpoint를 보존한다. 성공할 때까지 무제한 재시도하지 않는다.
- 일시적인 저장 오류는 정해진 횟수만 재시도한다. 학습 설정을 바꾸는 복구는 새 실험으로 구분한다.
- 승인된 복구 예산이 있으면 그 범위에서 진행하고 출처를 기록한다. 남은 예산이 없으면 조정자에게
  완료 범위와 필요한 추가 작업을 보고한다.
- 다른 담당자가 관리하는 파일이나 이미 실행 중인 설정을 동시에 수정하지 않는다.

## 후속 실험 제안

검증 담당의 결과를 받아 관찰과 가설을 구분한다. 훈련과 검증 모두 낮으면 학습·최적화 문제를,
훈련은 높고 검증이 낮으면 미로 다양성 등 일반화 문제를 후보로 삼는다. 이는 원인 확정이 아니다.
변수 하나의 변경, 예상 효과, 실패했을 때 알 수 있는 것, 필요한 예산을 적어 조정자에게 제안한다.
승인된 계획 밖의 제안은 실행된 결과처럼 쓰지 않는다.
